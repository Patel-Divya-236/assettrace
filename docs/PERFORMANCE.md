## How to read EXPLAIN output

- **Seq Scan**: Postgres reads every row of the table and checks each one. Cost grows with the table: 10× more assets, ~10× slower.
- **Index Scan**: Postgres walks a B-tree index straight to the matching rows (like a book's index), then reads only those rows. With `ORDER BY ... LIMIT 20` it can stop after 20 rows.
- **Bitmap Index Scan → Bitmap Heap Scan**: Postgres first collects the locations of all matching rows from the index, then reads those table pages in physical order. Used when many rows match, and for the GIN index on JSONB (`attributes @> '{...}'`).
- **Execution Time** is what the database actually spent; planning time is small and not shown.
